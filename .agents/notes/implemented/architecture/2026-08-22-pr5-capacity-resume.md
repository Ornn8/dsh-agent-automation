# PR5 capacity wait and resume

- Capacity-deferred change and review execution now publishes one strict `CapacityWaitProjection` v1 carrying the original WorkRequest id and revision, role, Profile/Workflow/Stage identity, definition hash, exact subject state, full WorkerRouteDecision v1, and sanitized capacity generation and observation ids.
- Issue and repair waits use the existing controller-authored status projection; review waits use a neutral exact-head `agent/review` CheckRun summary. Neutral review capacity is never treated as PASS or BLOCK.
- The existing landing schedule is the sole capacity wake source. Its backlog reconciliation always reads the newest bounded 100-item repository-wide Issue-comment page sorted by updated time, then reads one additional 100-item page from a 16-page rotation when selected; it merges and deduplicates the pages, parses each trusted projection's `issue_url`, and reads only the referenced current Issue or pull request. Subject and comment pagination are independent, new waits are discovered immediately, and deep pages do not starve. It selects only the newest trusted capacity-waiting projection whose subject remains open and exact. It reconstructs the original Issue WorkRequest or repair request, so a newly eligible Worker can serve the same task class without editing the Issue, Profile, or WorkRequest. The capacity-generation digest is retained for audit and is not a resume gate.
- Resume re-reads the current subject, trusted Profile/Stage, and local routing authority. Stale projections, terminal states, duplicate terminal comments, and route changes fail closed; CI repair reuses its existing Governor admission and consumes a budget attempt only when a Worker actually starts.
