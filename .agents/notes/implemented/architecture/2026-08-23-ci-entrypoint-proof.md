# Trusted CI execution identity proof

Configured Profiles now require advancement and landing to inspect the exact Actions job behind each required CheckRun and find one completed successful step whose name equals the trusted Verification Contract `procedure` or `entrypoint`.

This records a target-owned static execution equivalent without allowing the generic Controller to run product commands. The check run and job must share the exact head and required check name; an unparseable job URL, mismatched job, missing step, or unsuccessful step fails closed. Unconfigured Profiles skip the additional evidence and retain the existing behavior.
